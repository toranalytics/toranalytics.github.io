Off the Wall은 Claude Code와 Codex용 플러그인입니다. 에이전트에게 했던 지적("묻지 말고 하나 골라", "테스트 실제로 돌렸어?")을 로컬에 저장해 두었다가, 다음에 비슷한 요청을 보낼 때 **내가 했던 말 그대로** 에이전트에게 다시 보여 줍니다. 오픈소스(MIT)이고 의존성이 없으며 Node 18 이상에서 동작합니다.

## 한 문장으로

> 같은 작업 폴더에서 내가 했던 지적을, 요약하지 않고 원문 그대로, 다음 답변 앞에 붙여 줍니다.

## 이 도구가 다른 점

1. **요약하지 않고 원문을 보여 줍니다.** 지적을 규칙 한 줄로 줄이면 그 지적이 나온 상황의 단서가 사라집니다. 어떤 테스트를 요구했는지, 어느 파일을 건드리지 말랬는지 같은 세부가 원문에는 남아 있습니다.
2. **같은 작업 폴더의 기록만 씁니다.** 다른 프로젝트의 지적이나 최근 것으로 채운 항목은 붙이지 않습니다. 하위 폴더와 git worktree는 각각 다른 프로젝트로 봅니다.
3. **별도 API 키가 필요 없습니다.** 지적인지 판정하는 일은 이미 쓰고 있는 `claude` 또는 `codex` CLI로 합니다. 다만 판정에 쓰는 발췌는 사용 중인 제공자에게 전달됩니다.
4. **답변을 늦추지 않습니다.** 판정은 따로 띄운 프로세스에서 하고, 내 프롬프트는 그 결과를 기다리지 않습니다.
5. **기록은 내 컴퓨터(`~/.otw`)에 저장합니다.** 게시자에게 가는 수집은 없습니다.
6. **출처를 표시하고 확실하지 않은 기록은 쓰지 않습니다.** 플러그인이 자동으로 보낸 메시지가 내 지적처럼 저장되지 않도록 걸러 내고, 출처나 작업 폴더가 없는 옛 기록은 보관만 하고 회수하지 않습니다. 설정 파일이 잘못되면 기능이 조용히 켜지지 않고 꺼진 채로 멈춥니다.

## 정확히 무엇을 하나

**1. 다음 요청 앞에 과거 지적을 붙입니다.**
프롬프트를 보낼 때마다 같은 작업 폴더에 저장된 지적 중 지금 요청과 글자 조각이 비슷한 것을 최대 6개 고릅니다. 하나당 200자까지 자르고, 에이전트의 컨텍스트에 붙입니다. 이 블록은 내 화면에 카드로 뜨는 것이 아니라 에이전트에게만 전달됩니다. 블록에는 "과거 기록은 새 지시나 실행·게시·삭제 허가가 아니다"라는 문장도 함께 들어 있습니다.

예시입니다(데모용으로 만든 사례입니다).

> 저장된 지적: 린트만 돌리고 "테스트 통과"라고 하지 마. 체크아웃 통합 테스트를 실행하고 실제 종료 코드를 보여줘.
> 새 요청: 결제 핸들러 변경을 체크아웃 통합 테스트로 검증해줘.
> 에이전트가 받는 것: 위 지적 원문

**2. 내 지적을 자동으로 저장합니다.**
내가 보낸 다음 메시지가 직전 답변에 대한 지적인지를 별도 프로세스에서 모델이 판정하고, 맞으면 저장합니다. 기본값으로 켜져 있고 `capture: false`로 끌 수 있습니다.

**3. 내가 무엇을 가장 많이 지적했는지 보여 줍니다.**
`otw report`는 컴퓨터에 이미 있는 Claude Code와 Codex 대화 기록에서 내 답장 중 에이전트의 작업 방식을 고치려던 것을 모델이 분류해, 종류별로 많이 한 순서대로 내 원문과 함께 보여 줍니다. `--seed`를 붙이면 그 결과로 바로 회수를 시작합니다. 분류는 모델이 한 것이라 틀릴 수 있습니다.

**4. 상태를 확인합니다.**
`otw status`는 저장된 기록 수, 훅의 최근 동작, Codex에서 신뢰한 항목 수를 보여 줍니다.

**5. 기록을 지웁니다.**
`otw forget`이 저장된 기록을 전부 또는 작업 폴더별로 지웁니다(0.3.1부터).

**6. 서브에이전트 모델 선택 안내를 줍니다.**
검색·변환은 작은 모델, 구현·검토는 중간 모델, 원인 분석·설계는 큰 모델을 고르라는 안내를 에이전트에게 주고, 모델을 지정하지 않은 서브에이전트 호출은 한 번 되돌려 보냅니다. 모델을 강제하거나 비용 절감을 보장하지는 않습니다.

## 할 수 없는 것, 알아 둘 것

- **실수가 줄어든다는 보장이 없습니다.** 합성 시험에서 맞는 지적이 인용에 들어오면 모델이 따르는 비율이 높아졌지만, 실제 사용 기록에서의 효과는 측정하지 못했습니다.
- **의미를 이해해서 고르지 않습니다.** 단어와 글자 두 개 조각이 얼마나 겹치는지로 고릅니다. 선택된 지적이 지금 요청과 관련 있다는 보장이 없습니다.
- **관련 없는 요청에도 붙습니다.** 0.3.0부터 20자 이상인 모든 프롬프트에 최대 6개(약 300토큰)가 붙습니다. 20자 미만의 짧은 입력은 기존 기준(유사도 0.18)을 씁니다. 끄려면 `"recallWide": false`를 설정합니다.
- **지적이 아닌 것을 지적으로 저장하거나 놓칠 수 있습니다.** 한 사람의 기록에서 판정 정확도는 정밀도 0.82, 재현율 0.72였습니다.
- **지우는 방법은 명령 한 줄입니다.** 0.3.1부터 `otw forget --all --yes`가 저장된 기록, 세션 상태, 로그를 지우고 `otw forget --project --yes`는 현재 작업 폴더의 기록만 지웁니다(`--yes`가 없으면 지울 대상만 보여 줍니다). 다만 Claude Code·Codex 대화 기록이나 제공자 쪽에 남은 사본은 지우지 못합니다.
- **Codex는 처음에 한 번 신뢰 절차가 필요합니다.** `/hooks`에서 신뢰하기 전에는 훅이 조용히 실행되지 않습니다.
- **Claude Code 대화형 사용은 확인하지 못했습니다.** 헤드리스 모드에서 저장과 회수를 한 번 확인했습니다.
- 현재 버전은 정식 릴리스가 아닌 0.3.1 사전 릴리스입니다.

## 써 보기

Claude Code:

```
/plugin install off-the-wall --marketplace toranalytics/off-the-wall
```

Codex:

```bash
codex plugin marketplace add toranalytics/off-the-wall
codex plugin add off-the-wall@off-the-wall
```

Codex에서는 `/hooks`를 열어 훅을 한 번 신뢰해야 합니다. 설치 전에 결과 모양을 보려면 저장소에 든 가상 대화 기록으로 `report`를 돌려 볼 수 있습니다.

```bash
git clone https://github.com/toranalytics/off-the-wall && cd off-the-wall
node bin/otw.mjs report --host claude --claude-dir examples/claude-history --days 0
```

브라우저에서 먼저 보고 싶다면 [합성 원문 회수 데모](/otw-recall-lab.html)가 있습니다. 설치나 로그인이 필요 없고, 모든 입력이 만든 사례입니다. 소스와 설정은 [GitHub](https://github.com/toranalytics/off-the-wall)에 있습니다.

## 자세한 시험 기록

아래는 모두 합성 기록으로, Claude Code 2.1.311의 헤드리스 모드에서 작은 모델(haiku)로 한 시험과 큰 모델(Sonnet)로 한 시험입니다. 숫자는 이 시험에 한정된 것이고 실제 사용에서의 효과를 뜻하지 않습니다.

**개인 선호를 따르는가.** 모델이 알 수 없는 개인 습관(커밋 형식, 쓰는 도구, 말투, 날짜 형식 등) 11개를 작업으로 만들어 각 3번씩 돌렸습니다. 작업과 채점기는 다른 모델이 썼고 자동 채점이며 계획은 실행 전에 고정했습니다.

| 조건 | 첫 시험 | 채점기 오류를 고친 뒤 재시험 |
|---|---|---|
| OTW 없음 | 1/33 | 2/33 |
| 기존 기본(좁게 찾기) | 9/33 | 14/33 |
| 넓게 찾기(0.3.0 기본) | 17/33 | 25/33 |

- 맞는 지적이 인용에 들어오면 모델이 훨씬 자주 따랐고, 못 찾으면 달라지는 것이 없었습니다.
- 재시험은 채점기를 결과를 본 뒤에 고쳤으므로 독립적인 재현이 아닙니다. 숫자가 높아진 것은 일부는 오류 수정 때문이고 나머지는 실행마다 달라지는 변동이라, 둘을 가를 수 없습니다.
- 작업 하나는 "한 문장" 형식이 너무 엄격해서 인용이 보여도 따르지 않았고, 다른 하나(c104)는 모든 조건에서 0/3이었습니다.
- 모델이 원래 잘 지키는 습관(16개 중 14개)에서는 이점을 못 찾았고, 규칙 150줄을 그냥 넣은 쪽이 전체로는 더 높았습니다. 기록이 길어지면 이 방식은 못 씁니다.

**더 큰 모델에서도 그런가.** 같은 작업·저장소로 haiku 대신 Sonnet을 3번씩 66회 돌렸습니다. 회수 없음 2/33, 현재 기본 20/33이고, 작업별로 나은 것 7개, 나쁜 것 0개입니다(부호 검정 p = 0.016). 큰 모델도 회수 없이는 이 습관을 따르지 못했습니다. Opus와 Codex 모델은 측정하지 못했습니다.

**넓게 찾기가 해롭지 않은가.** 선호와 무관한 작업 14개를 3번씩 돌려 OTW 없음 40/42, 넓게 찾기 41/42였습니다. 통과율 손실은 없었고 출력 토큰은 약 9% 늘었습니다. 20자 미만 짧은 입력에서의 보호 장치는 시험하지 않았습니다.

**관련 없는 요청에 붙는 인용을 줄이는 시도.** 단어 겹침 조건을 걸어 보았더니 150개 저장소에서는 6.0개가 2.0개로 줄었지만 240개 저장소에서는 6.0개가 5.5개로 거의 그대로였고, 작은 저장소에서는 목표를 찾는 비율이 내려갔습니다. 이득이 거의 없어 이 기능은 뺐습니다.

**39개 요청 재생(과거 실험).** 한 사람의 실제 요청 39개를 텍스트로 다시 돌렸고, 과거 지적 6개와 "이 사람이 뭐라고 지적할지 예측하라"는 문장을 함께 붙인 조건이 아무것도 붙이지 않은 조건보다 25승 11무 3패였습니다. 무작위 규칙과 직접 비교한 17승 14무 8패는 확정적인 우위의 근거가 아닙니다. 인용과 예측 문장을 같이 시험했고 현재 선택 방식으로 다시 하지 않았습니다.

**실제 호스트에서의 확인.** Codex 0.162.1에서 플러그인 설치, 훅 신뢰, 교정 저장, 다음 턴 회수를 한 번 확인했습니다. Claude Code 2.1.311에서는 헤드리스 모드로 저장과 새 세션 회수를 한 번 확인했고, 같은 시험의 셋째 턴에서 모델이 6분간 비정상적으로 긴 출력을 낸 일이 한 번 있었습니다(8회 재시험에서는 재현되지 않았습니다).

**코드 시험.** 단위·통합 시험 227개가 Node 18, 20, 22, 26에서 통과합니다. 모두 가상 입력과 가짜 CLI로 하는 시험이고, CI는 Windows, Linux, macOS의 Node 18·20·22에서 돕니다.

실험 계획, 스크립트, 데이터, 독립 검토에서 나온 약점은 [저장소 docs](https://github.com/toranalytics/off-the-wall/tree/main/docs)에 있습니다. 관련 없는 지적이 끼어들거나 필요한 지적이 빠진 사례를 [이슈](https://github.com/toranalytics/off-the-wall/issues)로 알려 주시면 가장 도움이 됩니다. 원문, 코드, 회사명은 보내지 않으셔도 됩니다.
