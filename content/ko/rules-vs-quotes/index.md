> **쉽게 말하면.** 이 글은 실제 요청 39개를 글로만 다시 돌려 본 오래된 시험을 다룹니다. 개발자 본인의 과거 지적을 보여 주는 방식과 짧은 규칙을 비교한 것이고, 실제 사용에서 플러그인이 잘 동작한다는 증거는 아닙니다. 이후에 한 시험이 더 읽기 쉽습니다. 시험용으로 만든 개인 습관에서 Claude(Sonnet)는 Off the Wall이 없으면 33번 중 2번, 있으면 20번 따랐습니다. [쉬운 설명 글](/otw-what-it-does/)을 보세요.

>
> 2026-10-28 업데이트: 이후에 한 개인 선호 측정(회수 없음 1/33, 기존 기본 9/33, 넓게 찾기 17/33, 합성 작업)은 [Off the Wall 글](/off-the-wall/)에 있습니다. 넓게 찾기는 0.3.0부터 기본값입니다. 이 글의 재생 실험은 바뀌지 않았습니다.
>
> 2026-10-23 업데이트: 이 글은 과거의 재생 실험과 공개 플러그인이 실제로 보여 주는 것을 구분합니다. 규칙에 대한 일반적인 우위를 입증하지 않습니다.

교정에는 짧은 규칙이 빠뜨리는 세부가 들어 있을 수 있습니다. 어떤 테스트가 빠졌는지, 어떤 파일이 작업 범위 밖이었는지, 어떤 결정을 이미 위임했는지 같은 것들입니다. 이것이 [Off the Wall](https://github.com/toranalytics/off-the-wall)의 설계 질문입니다.

개인 기록을 연결하기 전에 **[합성 원문 회수 데모를 먼저 열어 보세요](/otw-recall-lab.html)**. 인터페이스는 한국어이고, 안에 포함된 JSON에 합성 프롬프트, 선택된 인용, 소스 버전, 실제 훅 출력이 표시됩니다.

## 인용은 결과가 아니라 장치입니다

직접 만든 예시는 이렇습니다. 린트 뒤에 성공을 주장하지 말고, 체크아웃 통합 테스트를 실행해서 종료 코드를 보여 달라는 것입니다. 이후에 관련된 요청이 오면 그 교정이 원문 그대로 프롬프트 컨텍스트에 들어갑니다.

데모는 공개 OTW 0.1.1(커밋 `07fe3d3d4f4accc153eb0684f506e0d3c206fdcc`)의 수정하지 않은 CLI 훅을 실행합니다. 합성 요청 4개, 빈 저장소와 채운 저장소, 두 호스트 모드를 합쳐 격리된 훅 실행 16회입니다. 개인 기록, 교정 판정기, 모델 답변, 실제 Claude Code/Codex 호스트 세션은 들어 있지 않습니다. 저장된 교정은 데모 제작자가 넣은 것입니다.

이것은 컨텍스트가 조립되는 과정과 미래 날짜의 fixture가 제외되는 것을 확인합니다. 모델이 인용을 따르는지, 실제 작업이 성공하는지, 사용자가 교정을 덜 반복하는지는 **확인하지 않습니다**.

## 예전 재생 실험이 보고한 것

과거 실험은 한 사람의 기록에서 요청 39개를 골랐고, 텍스트로 채점할 수 있는 교정으로 한정했습니다. Opus 5.5가 도구 없이 다시 답했고, Sonnet이 두 순서로 쌍을 비교해 두 순서가 일치할 때만 승리로 셌습니다.

과거 인용에 이의 예측을 더한 조건은 아무것도 붙이지 않은 조건에 25승 11무 3패로 보고됐습니다. 무작위로 요약한 규칙과 직접 붙으면 17/14/8이었고, 보고된 양측 p값은 약 0.11입니다. 우위의 결정적 증거가 아닙니다. 인용 형식과 예측 지시는 합쳐진 처치였고, 원문 문구만 따로 시험한 것이 아닙니다.

보존된 실행 기록은 보고된 합계와 조건을 뒷받침합니다. 원본 case별 출력은 이번 검토에서 독립적으로 다시 돌리지 않았습니다. 선택 편향, 한 사람, 모델 채점, 텍스트만 쓰는 작업이 결과를 제한합니다. 이 숫자들도, 모델이 반사실로 내린 평가도 측정된 방지율이 아닙니다.

가설은 교정의 세부를 남기면 나중의 관련 상황에서 도움이 될 수 있다는 것입니다. 이것은 행동에 대한 가설이고, 규칙이 효과가 없다는 일반적 발견이 아닙니다.

## 현재 데모도 틀리는 것

검증용 fixture는 다른 작업의 "로그인 파일만 고쳐라"라는 지시를 회수합니다. 완전히 무관한 요청도 최신 교정을 받습니다. 회수는 이전 요청에 대한 단어·문자 bigram TF-IDF를 쓰고 뒤이어 최근 항목을 붙입니다. 작업 범위는 해결하지 않습니다.

공개 컨텍스트 블록은 원래 요청의 범위 메타데이터 없이 교정을 인용합니다. 그래서 "이번 작업" 같은 문장은 가리키던 대상을 잃을 수 있습니다. 이것은 확인된 선택·컨텍스트 한계이고, 모델이 실패하는 것이 관찰된 것은 아닙니다.

지속적인 선호와 일회성 작업 제약을 나누는 것, 출처를 보여 주는 것, 무관한 최근 교정을 다루는 것은 이미 나온 기능이 아니라 제안된 제품 개선입니다. 자동 플러그인 메시지가 교정 분석에 들어갈 수 있었기 때문에, 사람 입력 경계 수정(출처 태그와 작업 디렉터리 기준 회수)이 0.2.0으로 공개됐습니다. 자동 입력을 모두 걸러 낸다는 증거는 없습니다.

## 개인정보와 모델 선택 안내

결과와 상태는 로컬에 저장되며 기본 위치는 `~/.otw`입니다. 판정과 개인 기록 리포트는 사용자의 Claude/Codex CLI를 통해 발췌문을 해당 모델 제공자에게 보냅니다. 별도 API 키가 없다는 것이 사용량, 비용, 한도, 제공자 측 처리가 없다는 뜻은 아닙니다.

플러그인은 오케스트레이터에게 모델 선택 안내도 제공합니다. 일반적인 자동 라우팅이나 비용 절감을 보장하지 않고, Codex 모델 매핑은 측정하지 않았습니다.

## 먼저 장치부터 써 보세요

개인 기록 업로드나 seed 명령이 아니라 [합성 데모](/otw-recall-lab.html)로 시작하세요. 이 글은 개인 `report --seed` 시작을 권하지 않습니다. 입력 경계 수정은 공개됐지만 실제 사용으로 검증되지는 않았습니다.

가장 쓸모 있는 피드백은 구체적인 것입니다. 필요한 인용이 빠졌는지, 무관한 인용이 나타났는지, 노출된 뒤에도 에이전트가 같은 실수를 했는지요. 개인 대화 기록, 코드, 회사명, 인증 정보 없이 [이슈를 열어 주세요](https://github.com/toranalytics/off-the-wall/issues). 설치 방법은 [현재 README](https://github.com/toranalytics/off-the-wall)에 있습니다.
