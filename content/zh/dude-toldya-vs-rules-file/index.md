对编码代理来说，习惯问题往往在规则文件里写一行就能解决。在 AGENTS.md 或 CLAUDE.md 里写上“提交信息用这个格式”就行了。那为什么还需要 Dude Toldya？为了回答这个问题，我在相同条件下直接做了比较。

先说结论：在这次测试里，规则文件的得分比 Dude Toldya 更高。


## 怎么比较的

模型是 Codex CLI 0.162.1 里的 GPT-6.1-Sol。习惯是我编造的 11 个，每个习惯有一个检查它的任务。每种条件每个任务跑 3 次，共 33 次。

- **什么都不做**：插件已安装，但关闭回忆。
- **规则文件**：关闭回忆，把 11 个习惯手写成一行一条的规则放进 AGENTS.md。
- **Dude Toldya**：开启回忆，调出已保存的纠正。

三种条件安装的是同一个插件版本（提交 d10e79f）。三者之间只有上面的设置不同。

## 结果

| 条件 | 遵循习惯的次数 |
|---|---|
| 什么都不做 | 8/33 |
| 规则文件（AGENTS.md） | 30/33 |
| Dude Toldya | 27/33 |

规则文件多 3 次。但这次测试无法说明这个差距是否有意义。独立审计只确认了 99 行数据没有重复、合计正确，没有得出哪一个更好的结论，也不能得出两者相同的结论。

## 解读这些数字时要注意的地方

三种条件展示给模型的内容不同。规则文件条件下，11 条规则每次都会全部放进去；Dude Toldya 则按每次请求挑出看起来相关的纠正，在一些任务上没有选中。有 6 次运行（两个任务，各 3 次），我在记录里没有找到目标纠正开头的句子。其中一个任务 Dude Toldya 是 0/3，规则文件是 3/3；另一个任务 Dude Toldya 是 3/3，规则文件是 1/3。

能否找到那句话本身也不是精确的指标。找不到不能证明目标纠正没有传到模型，找到了也不能证明它改变了回答。评分器只检查每个任务的特定条件，不评判回答的整体质量。

另外，这只是一个模型加 11 个编造的习惯。它不能说明 Claude Code、真实使用记录或其他模型的情况。

## 那么规则文件就够了吗？

如果习惯是你已经知道、也能写下来的，这次测试显示规则文件效果不错。对这类习惯，规则文件更简单。

Dude Toldya 想做的是另一件事：把你没有整理成规则、只存在于你在会话中说过的话里的内容再次带回来。这次测试没有测量这种情况，因为规则文件条件下的 11 个习惯是我事先整理好放进去的。当没有整理的纠正越积越多时，哪一个更好，这次测试无法回答。

所以我现在能说的有限：在 Codex 上用 11 个编造的习惯，Dude Toldya 比什么都不做更好（8/33 到 27/33），规则文件与它相同或更高（30/33）。更多结论需要你自己测量。

## 自己测量

仓库里的 `duto bench` 会用你自己的 `claude` CLI 运行 11 个习惯任务，分别在关闭回忆和开启回忆的情况下各跑一次。本文这个 Codex 与规则文件的比较不包含在这个命令里。这次比较用到的运行记录和规则我另行保存，公开之前还要决定以什么形式放进仓库。目前已公开的测试记录只有 [Claude Haiku 基准测试](https://github.com/toranalytics/dude-toldya/blob/main/docs/data/bench-public-031/result.md)。
